## How to Contribute

You can contribute by:

- fixing typos or broken links in tutorials
- improving documentation and explanations
- adding new beginner-friendly examples
- creating or refining notebooks
- adding small datasets or sample images when appropriate
- fixing bugs in example scripts
- suggesting new resources or topics
- helping organize lessons and chapters

## Project Goals

This repository aims to:

- teach computer vision concepts clearly and practically
- provide curated learning material and examples
- make CV learning accessible to beginners and intermediate learners
- connect theory with code and small projects

## Repository Structure

The repository is organized around educational chapters and resources. While the structure is still evolving, the goal is to keep content easy to navigate.

A typical contribution should fit into one of these areas:

- `README.md` or other docs
- chapter folders with markdown notes
- notebooks under `notebooks/`
- project examples under project-related folders
- code examples or utilities for educational purposes

Please keep files descriptive and consistent with the naming patterns already used in the repo.

## Contribution Guidelines

### 1. Before you start

- Check whether a similar issue or PR already exists.
- If you want to add a new topic, tutorial, or project, open an issue first to discuss the idea.
- Keep your scope focused to one change or improvement per PR when possible.

### 2. Use clear, descriptive titles

When creating a PR, use a title that clearly explains the change. Example:

- `Add OpenCV image filtering notebook`
- `Fix broken links in Chapter 3 markdown`
- `Improve setup instructions for local development`

### 3. Keep changes relevant

Avoid unrelated formatting changes. Try to keep pull requests limited to the topic they address.

### 4. Respect existing content

This repo is educational and curated. When adding new material:

- prefer correctness over novelty
- cite sources when appropriate
- avoid copy-pasting large external content without attribution
- maintain readability and clarity for learners

### 5. Large additions

If you are contributing a large tutorial, notebook, or project:

- split it into smaller commits if needed
- include a short summary in the PR description
- explain what the learner will get from it

## Pull Request Process

1. Fork the repository.
2. Create a branch for your change.
3. Make your edits.
4. Run any relevant checks or validation steps for your change.
5. Commit with a clear and descriptive message.
6. Open a pull request with:
   - a concise title
   - a brief description of the change
   - screenshots or sample output when relevant
   - links to issues if applicable

### PR checklist

Before submitting, confirm:

- [ ] The change is relevant to this repository
- [ ] The content is clear and understandable
- [ ] Links and references work when possible
- [ ] Code/notebooks run or have been checked for obvious errors
- [ ] File names and structure are consistent with the repo
- [ ] The PR description explains the purpose and scope

## Style Guidelines

### Markdown

- use clear headings and concise explanations
- keep tables readable and well formatted
- prefer simple language for educational content
- use relative links when possible

### Python

- follow PEP 8 where practical
- use descriptive variable names
- keep examples readable for learners
- avoid unnecessary dependencies in small examples

### Jupyter notebooks

- keep outputs concise when possible
- clear cells and sections are preferred
- ensure code cells are understandable and reproducible
- remove large generated outputs before committing when possible

### Naming conventions

- prefer clear, descriptive names
- avoid unnecessary special characters in file names
- keep folder names consistent and readable

## Reporting Issues

Please open an issue if you find:

- a broken link
- a typo or confusing explanation
- incorrect code example
- missing documentation or setup details
- a feature request for new learning material

When reporting an issue, include:

- the relevant file or chapter name
- a clear description of the problem
- expected vs actual behavior
- screenshots or code snippets when helpful

## Code of Conduct

We expect contributors to be respectful, constructive, and collaborative.

Please avoid:

- harassment or discriminatory behavior
- disrespectful commentary on issues or pull requests
- spam or low-quality contributions

We aim to maintain a welcoming, productive environment for learners and contributors.

## Questions?

If you are unsure where to contribute or how to structure a change, open an issue and ask. We are happy to help.

Thank you for helping improve this learning repository.
